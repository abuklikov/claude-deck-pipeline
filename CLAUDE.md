# Система генерации презентаций

Эта папка — рабочая среда для пайплайна, который превращает чаты с Claude в PPTX-презентации через 3 этапа с человеком в петле.

При работе в этой папке всегда учитывай этот файл и соответствующий `ARCHITECTURE.md`.

## Структура

- `templates/` — библиотека многоразовых PPTX-эталонов. Рядом с каждым `<name>.pptx` лежит `<name>.md` с описанием в 1-2 предложения (для кого, какой характер). При `/deck-start` пользователь может выбрать один как референс для новой презентации.
- `style/` — общие правила сборки PPTX (`build-rules.md`), не зависящие от стиля конкретной презентации.
- `decks/<имя>/` — одна папка = одна презентация. Стиль задаётся per-deck через `reference.pptx`.
- `decks/_template/` — эталон новой папки-deck, копируется командой `/deck-start`.

## Слэш-команды (`~/.claude/commands/`)

Основной пайплайн:
- `/deck-start <название>` — этап 0: содержательный диалог о теме, аудитории, цели → формирует `00-brief.md`.
- `/deck-resume <название>` — возврат к незаконченной презентации.
- `/storyline` — этап 1: обсуждение легенды и каркаса слайдов → `01-storyline.md`.
- `/content` — этап 2: наполнение слайдов текстом → `02-content.md`.
- `/build-deck` — этап 3: автоматическая сборка PPTX → `03-deck.pptx`.

Опциональные (запускаются по запросу пользователя):
- `/deck-critic` — критический разбор текущего артефакта.
- `/deck-research` — верификация фактов и цифр.

## Конвенции артефактов

В каждой папке `decks/<имя>/`:
- `00-brief.md` — аудитория, цель, тон, длительность, ограничения, ключевые тезисы. Заполняется в диалоге, а не как форма.
- `reference.pptx` — PPTX-эталон стиля для этой презентации. Опционально (если без него — билд использует минимальный дефолт).
- `reference-notes.md` — разбор `reference.pptx`: структура, сюжет, плотность текста, тон, визуальные элементы. Создаётся вместе с reference.
- `01-storyline.md` — каркас: список слайдов, на каждом — тип layout, заголовок, один ключевой месседж.
- `02-content.md` — наполнение: текст, буллеты, пометки визуала.
- `03-deck.pptx` — финальный файл.

Материал для презентации рождается в диалоге внутри команд `/deck-start` и `/storyline` — отдельный `transcript.md` не нужен. Если позже захочется поднять, что именно обсуждалось, лог сессии лежит в `~/.claude/projects/<encoded-cwd>/<session-id>.jsonl`.

**Имя папки deck:** `YYYY-MM-DD-<краткое-название>` (напр. `2026-04-30-strategy`).

## Принципы

1. **Человек в петле.** Каждый артефакт ратифицируется пользователем перед фиксацией. После фиксации команда не висит молча: она либо переходит к следующему этапу (автономный режим), либо явно спрашивает (ручной режим) — см. принцип 6.
2. **Артефакты — это правда.** Всё состояние пайплайна живёт в файлах, не в памяти чата. Любую команду можно прервать и вернуться к ней через неделю.
3. **Стиль — per-deck.** Стиль конкретной презентации задаётся через `reference.pptx` в её папке. Общий `style/build-rules.md` — только технические правила работы с PPTX.
4. **Каждая команда — самодостаточный плейбук.** Файл слэш-команды описывает: какие файлы читать, как общаться с пользователем, что записывать на выходе, когда останавливаться.
5. **Внешний поиск — сначала источники, потом запросы.** Когда команда вызывает research / WebSearch / WebFetch, она сначала **предлагает пользователю список из 5-15 источников** одним сообщением, ждёт согласия (или правок), и только потом фетчит. Не дёргает разрешение на каждый URL по отдельности.
6. **Режим пайплайна — per-deck.** В начале `/deck-start` пользователь выбирает: **автономный** (команды переходят между фазами сами, останавливаются только на содержательных развилках) или **ручной** (после каждой фазы команда явно спрашивает "запустить следующий?"). Выбор хранится в `decks/<имя>/.mode` одной строкой (`autonomous` / `manual`). Все команды пайплайна читают этот файл при старте; если его нет — спрашивают.
