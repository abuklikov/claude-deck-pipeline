# /build-deck

Ты — этап 3 пайплайна, последний. Архитектура полностью описана в `~/presentations/CLAUDE.md` и `~/presentations/ARCHITECTURE.md` — прочитай их в начале работы, если ещё не читал.

## Что ты делаешь

Берёшь утверждённый `02-content.md` и собираешь `03-deck.pptx`. Это техническая, не творческая фаза — формулировки уже зафиксированы. Твоя задача — превратить markdown-структуру в PPTX, унаследовав стиль из `reference.pptx` (если есть).

## Шаг 0 — Выбор активного deck

`$ARGUMENTS` — имя папки. Если передан:
- Проверь, что в папке есть заполненный `02-content.md`.
- Если нет — остановись и сообщи, что сначала нужен `/content`.

Если `$ARGUMENTS` пуст:
- Найди свежий deck с заполненным `02-content.md` по mtime.
- Уточни кандидата у пользователя или покажи список.

## Шаг 0.5 — Режим пайплайна

Прочитай `decks/<имя>/.mode`. Если файла нет — спроси (как в `/content`) и сохрани.

## Фаза 1 — Сборка

### Подготовка

Прочитай:
- `decks/<имя>/02-content.md` — источник правды по тексту слайдов.
- `decks/<имя>/reference-notes.md` (если есть) — какие визуальные приёмы заявлены.
- `~/presentations/style/build-rules.md` (если есть) — общие технические правила.

Проверь окружение Python: `python-pptx` должен быть в `~/presentations/.venv/`. Если venv нет — создай: `python3 -m venv ~/presentations/.venv && ~/presentations/.venv/bin/pip install python-pptx`.

### Парсинг контента

Структурируй `02-content.md` в список слайдов. Для каждого слайда вытащи:
- Тип layout (из заголовка `## Слайд N — <тип>`).
- Заголовок.
- Подзаголовок (если есть).
- Тело: буллеты, колонки, таблицы, нумерованные списки.
- Визуал: что должно быть рядом (иконки, графики, якорные цифры).
- Заметки спикера (если есть).

Парсь сам, не запускай отдельный парсер — markdown простой, разделение `---` между слайдами.

### Стратегия сборки

**Если есть `reference.pptx`:** открой его через python-pptx, наследуй размер слайдов (`slide_width`, `slide_height`) и slide masters. Используй пустой layout (обычно `slide_layouts[5]` или `[6]`) и добавляй shape'ы программно — это надёжнее, чем пытаться маппить наши типы layout на конкретные layout-индексы из reference (они в разных PPTX разные).

**Если `reference.pptx` нет:** стартуй с пустой презентации 16:9 (`Presentation()`, slide_width = 12192000 EMU = 13.33", slide_height = 6858000 EMU = 7.5").

### Маппинг типов layout на shape-композиции

Опиши простой набор раскладок для основных типов из палитры (см. `reference-notes.md`):

- **Титульный** — крупный текст по центру (ALL CAPS), подзаголовок ниже, нумерация "01" в углу.
- **Двухколоночный обзор / контраст** — две колонки одинаковой ширины с подзаголовками, буллеты внутри. Опционально цифра-якорь над колонкой.
- **Трёхколоночный контраст** — три колонки, подзаголовки сверху, буллеты внутри.
- **Сценарии-предложение** — таблица сценариев (2-3 столбца) + два текстовых блока ниже ("Предпосылки" / "Предложение").
- **Таблица результатов с выводами** — таблица + блок "Выводы" справа или снизу.
- **Next steps + open questions** — слева нумерованные блоки с крупными цифрами (01, 02), справа маркированный список вопросов.
- **Дорожная карта** — горизонтальная сетка по времени с цветными блоками-этапами.

Для каждого типа реализуй функцию `add_<type>_slide(prs, slide_data)`, которая создаёт слайд и добавляет нужные shape'ы. Размеры/координаты — в долях от slide_width/height, чтобы работало для любого размера.

### Реализация

Напиши Python-скрипт `decks/<имя>/_build.py` (временный, не финальный артефакт), который:
1. Открывает reference.pptx или создаёт новую.
2. Удаляет существующие слайды (если использовал reference как темплейт) — через манипуляции с XML, python-pptx сам не умеет.
3. Идёт по списку слайдов из распарсенного 02-content.md.
4. Для каждого слайда вызывает соответствующий `add_<type>_slide`.
5. Сохраняет в `decks/<имя>/03-deck.pptx`.

Запусти через `~/presentations/.venv/bin/python decks/<имя>/_build.py`. Если ошибка — диагностируй и правь скрипт. Если успех — проверь, что файл создался и его размер вменяемый (>10KB).

### Заметки спикера

Если в `02-content.md` есть **Заметки спикера**, добавляй их в `slide.notes_slide.notes_text_frame.text` для каждого слайда.

## Фаза 2 — Итерации

После первой сборки скажи пользователю: *"Собрал `03-deck.pptx`. Открой и посмотри. Что подправить?"*

Типы правок:
- **Текст** — это правка `02-content.md`, не build-deck. Скажи: *"Это контент — давай вернёмся в `/content`, там поправим, и я пересоберу."*. После правки контента — пересобираешь.
- **Раскладка** ("колонки слишком узкие", "цифра не там") — правишь функцию `add_<type>_slide`, пересобираешь.
- **Стиль** ("шрифт другой", "цвет акцента не тот") — если не наследуется автоматически из reference, делаешь явно через python-pptx (font.name, font.color.rgb).
- **Глобальные** — итерируешь по всем слайдам через ту же функцию.

После каждой правки пересобирай и подтверждай: *"Пересобрал, посмотри слайд N."*

## Фаза 3 — Фиксация

Когда пользователь подтверждает финал (*"ок", "годится"*):

1. Удали временный `_build.py` (он не нужен для дальнейшей жизни deck — артефакт сборки, не источник правды).
2. Подтверди: *"Готово. Файл: `decks/<имя>/03-deck.pptx`. Пайплайн завершён."*
3. Дальше — по режиму:
   - **`autonomous`:** пайплайн закончен, останавливайся. Это последний этап, переходить некуда.
   - **`manual`:** так же — это последний этап, дополнительного вопроса не нужно.

## Принципы

- **Не правь текст.** Источник правды — `02-content.md`. Если хочется поправить формулировку — сначала правка в `/content`, потом пересборка.
- **Один Python-скрипт на сборку.** Не плоди файлы. `_build.py` — временный, удаляется в фазе 3.
- **Размеры — в долях от slide_width/height.** Чтобы PPTX работал и в 16:9 4:3.
- **Шрифты и цвета — из reference, если есть.** Не выдумывай палитру. Если reference нет — используй системный дефолт (Calibri/Arial).
- **Заметки спикера переносятся как есть.** Не редактируй их при сборке.
- **Если что-то не парсится — упрощай и спрашивай.** Чем сложнее python-pptx-логика, тем больше шанс багов. Лучше простой PPTX без анимаций, чем сложный со сломанной разметкой.
